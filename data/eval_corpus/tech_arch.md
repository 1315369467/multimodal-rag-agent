# 微服务技术架构设计文档

## 第一章 架构概述

### 1.1 系统定位
本系统为公司核心业务中台，承载订单管理、库存管理、支付结算、用户中心四大核心领域。采用微服务架构，基于Spring Cloud Alibaba技术栈构建，支持日均千万级订单处理能力。

### 1.2 技术选型
服务框架：Spring Boot 3.2 + Spring Cloud Alibaba 2023。服务注册与发现：Nacos 2.3.0。配置中心：Nacos Config。服务网关：Spring Cloud Gateway。负载均衡：Spring Cloud LoadBalancer。熔断降级：Sentinel 1.8.7。分布式事务：Seata 2.0。消息队列：RocketMQ 5.1。缓存：Redis 7.0 Cluster模式。数据库：MySQL 8.0 + ShardingSphere 5.4分库分表。搜索引擎：Elasticsearch 8.11。

### 1.3 部署架构
生产环境部署在阿里云杭州区域，采用多可用区高可用部署。Kubernetes集群规模为30个worker节点（8核32G），使用Istio服务网格管理服务间通信。CI/CD流水线基于GitLab CI + ArgoCD实现GitOps自动化部署。监控告警使用Prometheus + Grafana + AlertManager体系。日志采集使用Filebeat + Kafka + Elasticsearch + Kibana（EFK架构）。

## 第二章 订单服务

### 2.1 订单状态机
订单生命周期包含以下状态：待支付(PENDING_PAY) → 已支付(PAID) → 待发货(PENDING_SHIP) → 已发货(SHIPPED) → 已签收(RECEIVED) → 已完成(COMPLETED)。异常状态：已取消(CANCELLED)、退款中(REFUNDING)、已退款(REFUNDED)。订单超时未支付自动取消时间为30分钟，使用RocketMQ延时消息实现。

### 2.2 订单分库分表策略
订单表按用户ID取模分为64个库、每库16张表，共计1024张表。分片键为user_id，路由算法为user_id % 64确定库，(user_id / 64) % 16确定表。历史订单（超过6个月）自动归档至HBase冷存储，归档任务通过XXL-JOB每日凌晨2:00执行。

### 2.3 幂等性保障
订单创建接口采用Token令牌机制保障幂等：客户端先请求获取唯一Token，提交订单时携带Token，服务端通过Redis SETNX原子操作判断Token是否已使用。支付回调接口通过交易流水号（trade_no）去重，数据库唯一索引+应用层双重校验。

## 第三章 库存服务

### 3.1 库存模型
库存采用三层模型：实物库存（仓库实际存量）、可售库存（可供前台销售的数量）、锁定库存（已下单未出库的数量）。关系为：可售库存 = 实物库存 - 锁定库存 - 安全库存。安全库存阈值由运营按SKU维度配置，低于阈值自动触发补货预警。

### 3.2 库存扣减方案
采用"预扣-确认-释放"三阶段方案：下单时预扣库存（Redis原子扣减+数据库乐观锁），支付成功后确认扣减，支付超时或取消后释放预扣库存。Redis中使用Hash结构存储SKU库存，HINCRBY命令保证原子性。每10分钟执行一次Redis与MySQL库存一致性校验任务。

### 3.3 超卖防控
多重防控机制：第一层Redis原子扣减（HINCRBY返回值<0则拒绝）；第二层数据库乐观锁（UPDATE stock SET available=available-? WHERE sku_id=? AND available>=?）；第三层异步对账任务（每小时检查订单量与库存变更量一致性）。极端情况下的少量超卖通过运营人工介入处理。

## 第四章 支付服务

### 4.1 支付通道
系统对接以下支付通道：支付宝（即时到账、APP支付、H5支付）、微信支付（JSAPI、Native、APP、H5）、银联云闪付、公司余额支付。支付路由根据交易金额、通道费率、通道可用性综合决策。单笔交易金额超过50000元自动触发风控审核。

### 4.2 对账系统
每日凌晨4:00自动拉取各支付通道T-1日的交易对账文件。对账流程：1)解析各通道对账文件；2)与本地交易流水逐笔比对；3)标记差异交易（长款、短款、金额不一致）；4)生成对账报告并邮件通知财务。差异率超过0.1%自动触发告警。历史对账成功率为99.97%。

### 4.3 退款流程
退款申请经客服审核通过后，系统发起原路退款请求。支付宝退款通常在1-3个工作日到账，微信退款在1-5个工作日到账。退款金额不得超过原交易金额，部分退款支持多次操作直至全额退完。退款状态通过支付通道异步回调更新。

## 第五章 性能与安全

### 5.1 性能指标
核心接口性能要求：订单创建接口P99延迟<200ms，QPS>5000；商品详情页P99延迟<100ms，QPS>20000；支付回调处理P99延迟<500ms。系统整体可用性目标为99.95%（年度停机时间<4.38小时）。数据库读写比约为8:2，通过Redis缓存将数据库QPS降低70%。

### 5.2 安全措施
接口安全：所有外部API通过API Gateway统一鉴权，采用JWT Token + OAuth2.0方案。数据安全：敏感数据（手机号、身份证、银行卡号）采用AES-256加密存储，日志输出时自动脱敏。传输安全：全站HTTPS，内部服务间通信使用mTLS双向认证。SQL注入防护：使用参数化查询，禁止拼接SQL。XSS防护：输出编码+CSP策略。
